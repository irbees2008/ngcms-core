# Интеграция SQLite в NGCMS

> SQLite сейчас поддерживается в установщике и базовом подключении ядра в
> экспериментальном режиме. Подготовленная схема создаётся отдельным
> установщиком; NGPDO адаптирует ряд часто используемых MySQL-выражений.
> Совместимость всех действий и плагинов, дампов/восстановления и обновления
> схемы не подтверждена. Сравнение строк также отличается от MySQL
> `utf8mb4_unicode_ci`. Для production-сайтов используйте MySQL.

## Описание

Этот гайд описывает, как интегрировать SQLite в качестве альтернативной базы данных для NGCMS, позволяя пользователям выбирать тип БД при установке.

## Преимущества SQLite

- **Легкое развертывание** - БД это просто файл
- **Нет необходимости в отдельном сервере БД** - идеально для общих хостингов
- **Автономность** - не требует запущенного MySQL сервера
- **Простота резервного копирования** - копируем файл БД
- **Меньше ресурсов** - подходит для маленьких сайтов

## Недостатки SQLite

- **Ограниченная масштабируемость** - для больших объемов данных
- **Ограниченный параллелизм** - блокировка на запись
- **Меньше возможностей** - не поддерживает некоторые MySQL функции

## Архитектура решения

### 1. Модифицирование класса NGPDO

`engine/classes/NGPDO.class.php` поддерживает MySQL и SQLite. Для SQLite используется
параметр `dbtype = sqlite` и абсолютный `dbpath`; на PHP с отдельным драйвером
`Pdo\Sqlite` используется его актуальный API, на более старых версиях — PDO SQLite API.
SQL-адаптер поддерживает только часть распространённых MySQL-конструкций и функций,
поэтому полной совместимости пока нет.
SQLite поддерживает `LAST_INSERT_ID()` без аргументов через последний вставленный
rowid текущего соединения. Как и в SQLite, явная вставка rowid тоже его меняет;
вариант MySQL `LAST_INSERT_ID(expr)` не поддерживается.
Для списка изображений и файлов поддерживается `FROM_UNIXTIME` с форматом
даты и фильтрация по месяцу; поддерживается тот же набор форматов, что и в
SQLite-адаптации `DATE_FORMAT`, а не все форматы MySQL.
Обновление и удаление сессии в `auth_basic` для SQLite используют подзапрос с
`LIMIT 1`: это не требует опции сборки SQLite для `UPDATE` и `DELETE` с `LIMIT`.
В публичных списках новостей и списке админки подсказки `FORCE INDEX`
применяются только для MySQL; на SQLite индекс выбирается планировщиком базы данных.
Отложенные просмотры новостей обрабатываются пакетами в SQLite-транзакциях
записи; при ошибке текущий пакет откатывается, а очередь читается без кэша.
При очистке старых записей нагрузки и журнала SQLite не выполняет MySQL-команду
`OPTIMIZE TABLE`; автоматический `VACUUM` не запускается.
В системных настройках для SQLite отображается путь к файлу без возможности
переноса, а параметры подключения MySQL скрыты. Проверка соединения использует
текущий файл; автоматическое резервное копирование SQLite не поддерживается.
На странице статистики отображается версия используемой SQLite вместо подписи MySQL.

### 2. Модификация установщика

`engine/install.php` предлагает выбор MySQL или SQLite. При выборе SQLite поля
подключения MySQL не требуются; установщик проверяет абсолютный путь и права PHP,
создаёт файл при подключении и устанавливает отдельную схему из
`engine/trash/tables.sqlite.sql`.
Установщик таблиц плагинов также обрабатывает базовые MySQL-конструкции `DESCRIBE`,
`AUTO_INCREMENT`, вторичные индексы и параметры charset/engine. Для SQLite-установки
плагина `quotes` MySQL-only перенос charset пропускается. Совместимость работы
плагинов после установки ещё не подтверждена.

### 3. Миграция SQL схемы

Схема SQLite поддерживается отдельно от MySQL-схемы. Не все запросы CMS и плагинов
адаптированы; резервное копирование, обновление схемы и все действия сайта ещё
нужно проверить на SQLite.

## Реализация

Подключение выполняется через `NGPDO`; установщик создаёт файл и таблицы SQLite,
после чего записывает `dbtype` и `dbpath` в конфигурацию. При изменениях нужно
сохранять отдельный путь MySQL и проверять SQL-запросы, которые проходят через
`NGPDO`, а также код, использующий специфичный для MySQL синтаксис напрямую.

## Файлы для модификации

1. **engine/classes/NGPDO.class.php** - добавить поддержку SQLite
2. **install.php** - добавить выбор БД

## Шаги установки со слектором БД

### Шаг 2 (измененный): Настройка БД

Пользователь видит выбор:
```
○ MySQL (требует отдельного сервера)
  Хост: [localhost]
  База: [database]
  Пользователь: [root]
  Пароль: [****]

○ SQLite (автономная БД, рекомендуется для малых сайтов)
  Путь к файлу: [/path/to/database.sqlite]
```

## Совместимость SQL

### Различия в синтаксисе

| Функция | MySQL | SQLite |
|---------|-------|--------|
| AUTO_INCREMENT | AUTO_INCREMENT | AUTOINCREMENT |
| Последний ID | LAST_INSERT_ID() | last_insert_rowid() |
| UNSIGNED | UNSIGNED | - (не поддерживается) |
| Проверка существования таблицы | SHOW TABLES | sqlite_master |
| CHARSET | CHARACTER SET utf8mb4 | - (UTF-8 по умолчанию) |

### SQL запросы для проверки

```sql
-- MySQL
SELECT DATABASE();
SHOW TABLES;

-- SQLite
PRAGMA database_list;
SELECT name FROM sqlite_master WHERE type='table';
```

## Инициализация БД

При первой установке с SQLite необходимо:

1. Создать файл БД
2. Выполнить SQL скрипты создания таблиц
3. Вставить начальные данные

**Рекомендация:** Создавать файл БД в папке `engine/conf/` или отдельной папке `data/`

## Хранилище БД SQLite

```
Рекомендуемые пути:
/engine/conf/database.sqlite    - компактно, вместе с конфигом
/data/database.sqlite            - отдельно для лучшей организации
```

## Безопасность

### Защита файла SQLite

Файл БД должен быть защищен от скачивания:

```apache
# .htaccess в папке с БД
<FilesMatch "\.sqlite$">
    Deny from all
</FilesMatch>
```

### Строка подключения в конфиге

```php
$config['dbtype'] = 'sqlite';
$config['dbpath'] = '/absolute/path/to/database.sqlite';
```

## Резервное копирование

### SQLite

Простое копирование файла БД:
```bash
cp engine/conf/database.sqlite backups/database.sqlite.bak
```

### Предложение в админке

В разделе резервных копий показывать опцию:
- Для MySQL: Экспорт SQL дампа
- Для SQLite: Скачивание файла БД

## Миграция между БД

Возможны сценарии миграции:
1. **MySQL → SQLite** (экспорт и импорт данных)
2. **SQLite → MySQL** (экспорт SQLite в SQL, импорт в MySQL)

Рекомендация: Использовать PHP скрипт для миграции, преобразующий данные и адаптирующий SQL синтаксис.

## Ограничения SQLite в контексте NGCMS

1. **Многопользовательский доступ** - SQLite заблокирует БД при записи
2. **Масштабируемость** - не рекомендуется для сайтов с большим трафиком
3. **Функции** - некоторые функции MySQL недоступны в SQLite
4. **Полнотекстовый поиск** - FTS модуль в SQLite менее мощный

## Рекомендации по использованию

### Используйте SQLite для:
- Разработки/тестирования
- Маленьких персональных сайтов
- Стартапов с низким трафиком
- Демо-версий

### Используйте MySQL для:
- Production среды
- Высоконагруженных сайтов
- Многопользовательских систем
- Сложных запросов и операций

## Реализация с сохранением текущей функциональности

**Важно:** При реализации нужно:
1. Не нарушать текущую MySQL функциональность
2. Сделать SQLite опциональным выбором
3. Обеспечить переключение между БД в админке
4. Предусмотреть миграцию данных

## Тестирование

Точечные тесты `test_sqlite_schema.php`, `test_sqlite_compat.php`,
`test_install_sqlite_validation.php` и `test_sqlite_news_counters.php` проверяют
схему, часть SQL-совместимости, установку и отложенные счётчики просмотров.
Они проходят на PHP 8.2 и 8.5.
Полный запуск CMS, функциональные сценарии, MySQL-регрессии, резервное копирование,
восстановление и нагрузочное тестирование ещё не подтверждены.
